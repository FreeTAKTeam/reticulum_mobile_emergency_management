# Offline vector maps for REM (issue #243): investigation

Status: proposal · Author: Claude for Giu · 2026-10-16
Issue: [#243 Offline vector maps (MBTiles) with civilian POI layer](https://github.com/FreeTAKTeam/reticulum_mobile_emergency_management/issues/243) · Milestone v1.5 (due 2026-11-16)

## 1. Where REM stands today

- The map is **MapLibre GL JS `^6.4.1`** running inside the Capacitor WebView (`apps/mobile/src/views/TelemetryMapView.vue`).
- The "Base" layer is the **online** OpenFreeMap Liberty style: `https://tiles.openfreemap.org/styles/liberty` (`utils/telemetryMapModel.ts`). Its tiles use the OpenMapTiles schema.
- The "Satellite" layer is **online** Esri World Imagery raster.
- Markers, SOS trails, plugin map sessions and map-marker replication (#280, #283–#290) are all built on the GL JS `Map` object.

So with no connectivity there is no basemap at all. Markers still work, but they float over a blank canvas.

## 2. Recommendation (short version)

| Decision | Choice | Why |
|---|---|---|
| Renderer | **Keep MapLibre GL JS** (do not switch to MapLibre Native) | Already shipping. All of the marker, plugin and SOS code depends on it. Native would mean a native view under the WebView and a rewrite of #280. |
| Tile format on device | **PMTiles** as the primary format, plus an **MBTiles import** for sideloading | PMTiles is one file with no SQLite. You can cut a region from a remote planet file with a single `pmtiles extract`. MBTiles stays supported because the issue asks for it and people already have such files. |
| Tile data | **Protomaps daily OSM basemap** (ODbL), cut into regional packs | Open data and open code. Daily builds. Regional cut-outs come from HTTP range reads, so you never download the 120 GB planet. |
| Style | Local style JSON generated by **`@protomaps/basemaps`** (light, dark and other flavors), with **bundled glyphs and sprites** | Nothing is fetched at runtime. Dark flavor works for night operations. |
| How tiles reach MapLibre | **Native tile handler** on Android: intercept `https://localhost/_rem_tiles/{pack}/{z}/{x}/{y}` in the WebView client and read from the archive | Capacitor's local file server is broken for HTTP Range requests (see §4), so loading `pmtiles://` straight from a `_capacitor_file_` URL is not safe. |
| Emergency POIs | A **separate POI pack** extracted from OSM (hospital, fire station, school, pharmacy, fuel, police, shelter…), drawn as a GeoJSON layer | Basemap POIs only exist at high zoom and you can't query them. "Nearest ER" needs a searchable dataset. |
| Personal pins | **Reuse the existing map-marker system** (#280/#285 replication) | That is already built. MECP is only needed as a compact encoding over LoRa. |

## 3. Options considered

### 3.1 Data source / schema
1. **Protomaps basemap (recommended).** Daily planet builds at `maps.protomaps.com/builds`, about 120 GB, z0–15. Each extra zoom level roughly doubles the size. Regional packs come from `pmtiles extract <planet> out.pmtiles --region=area.geojson --maxzoom=15`, which reads only the needed byte ranges. The data is an ODbL Produced Work, so attribution "© OpenStreetMap contributors" is required. The POI layer already includes `hospital`, `fire_station`, `school`, `fuel` and `shelter` kinds. Vendor rule: copy builds to our own storage, don't hotlink.
2. **OpenMapTiles schema via OpenFreeMap or Planetiler.** This keeps today's Liberty look. OpenFreeMap publishes weekly planet MBTiles, but only for the whole planet (no regional extracts). Its public tile API **limits offline downloads to 3,000 tiles or 50 MB**, so an in-app "download this area from tiles.openfreemap.org" feature isn't allowed at useful sizes. The workable route is to generate regions ourselves with Planetiler (Apache-2.0) using the OpenMapTiles profile (attribution required). This is more pipeline work than option 1.
3. **MapLibre Tiles (MLT).** A new columnar format, up to 6× smaller on large tiles, and supported in GL JS and Native. In January 2026 MapLibre still described it as for "the adventurous", and production tooling (Planetiler output) was still coming. **Watch it for v1.6+, but not for v1.5.**

### 3.2 Getting tiles from disk into the WebView
| Approach | Pros | Cons |
|---|---|---|
| A. `pmtiles://` with a `_capacitor_file_` URL | Zero native code | **Broken.** Capacitor's Android `WebViewLocalServer` ignores the end of a Range request, returns the rest of the file, and sends `206` headers that don't match the body ([ionic-team/capacitor#8371](https://github.com/ionic-team/capacitor/issues/8371)). One tile read can pull hundreds of MB into memory. |
| B. pmtiles JS custom `Source` whose `getBytes(offset,len)` calls a Capacitor plugin | Pure JS rendering; same code on iOS | Every read crosses the bridge as base64, which adds about 33% and JSON overhead. Acceptable for a spike, but slow when panning. |
| **C. Native request interception (recommended)** | MapLibre sees an ordinary `{z}/{x}/{y}` vector source. No Range semantics and no base64. Works for PMTiles and MBTiles (Android has SQLite built in). | Some Java or Rust code (a PMTiles header and directory reader is small). iOS needs its own `WKURLSchemeHandler` path. |
| D. Switch to MapLibre Native Android (has `pmtiles://file://` since 11.7.0) | Best rendering performance | Throws away the GL JS map stack, the plugin map API and the DOM markers. Out of scope for v1.5. |

For C, put the archive reader behind a small `TileArchive` interface (`PmtilesArchive`, `MbtilesArchive`). Two places it could live:
- **Java, in the Android layer**, next to `ReticulumNodeMapMarkerPluginApi.java`. This is the fastest spike.
- **Rust, in `crates/reticulum_mobile`**, using the `pmtiles` crate. iOS could then reuse it later. JNI on the tile hot path needs measuring.

Verify in the spike: (a) installing a custom `BridgeWebViewClient` doesn't break Capacitor's own asset serving; (b) requests from MapLibre's **web worker** reach `shouldInterceptRequest`; (c) MBTiles TMS row flip, `y = 2^z - 1 - y`.

## 4. Proposed architecture

```
Region pack (file)                 Android native                       WebView (Vue)
──────────────────                 ──────────────                       ─────────────
halifax.pmtiles  ─┐                TileArchiveRegistry                  offlineMapStyle(packs)
ns.mbtiles       ─┼─ import ─▶ filesDir/maps/ ─▶ PmtilesArchive    ◀─── GET https://localhost/_rem_tiles/
world-z0-6.pmtiles┘ (SAF picker)              └▶ MbtilesArchive         {pack}/{z}/{x}/{y}  (vector source)
                                                                     ◀── /map-assets/glyphs, sprites (bundled)
emergency-pois.geojson(.gz) ─────────────▶ POI store (SQLite/Rust) ──▶ GeoJSON source + "nearest" search
```

1. **Pack manager** (Settings → Offline maps). Import a `.pmtiles` or `.mbtiles` file with the system file picker and copy it into app storage. Show name, bounds, zoom range, size, OSM date and attribution, all read from the archive metadata. Allow delete. Optionally add a **download catalog** of prebuilt regional packs hosted by the project (GitHub Releases allows up to 2 GB per asset, or a FreeTAKTeam server).
2. **Bundled world overview.** Ship a tiny z0–5 world pack so the map is never blank, even with no packs installed.
3. **Style.** Build `StyleSpecification` at runtime: one vector source per installed pack (`tiles: ["https://localhost/_rem_tiles/<id>/{z}/{x}/{y}"]`, `bounds`, `minzoom`/`maxzoom` taken from metadata), plus `@protomaps/basemaps` `layers()` for each. Point glyphs and sprites at `/map-assets/...` inside `dist/`.
4. **Layer menu.** Add "Offline" (and an optional "Offline dark") next to Base and Satellite. Use offline automatically when the device has no network or the online style fails to load. Satellite stays online-only, because Esri imagery can't be cached under its terms. Tell the user that plainly.
5. **Coverage UX.** When the viewport is outside every installed pack's bounds, show "No offline map for this area. Import a region pack."
6. **Attribution.** Keep MapLibre's attribution control and add "© OpenStreetMap contributors" plus Protomaps (or OpenMapTiles) attribution.

## 5. Emergency POI layer

Rendered basemap POIs aren't enough on their own. Build a separate pack per region:

```bash
# Geofabrik regional PBF (ODbL) → filtered POIs → GeoJSON
osmium tags-filter nova-scotia-latest.osm.pbf \
  nwr/amenity=hospital,clinic,pharmacy,fire_station,police,school,fuel,shelter \
  nwr/emergency=ambulance_station,assembly_point -o pois.osm.pbf
osmium export pois.osm.pbf -o emergency-pois.geojson   # then reduce polygons to centroids
```

Keep `name`, `amenity`, `emergency`, `phone`, `opening_hours`, `addr:*` and `healthcare:speciality`. This supports a "nearest hospital or pharmacy" list sorted by distance from the last GPS fix.

Use the **capability-state separation** proposed in the #243 comment thread:

- `location_known` comes from the dataset, along with its OSM date.
- `operating_state` is one of `open | closed | limited | unknown`. It defaults to **unknown** and can only be set by a team observation (author and time).
- Hazard overlays such as "Blocked Road" are map markers with author, observed time and expiry. When one expires, the route goes back to *unknown*, never to "clear".
- UI wording example: "Hospital location cached. Current operating status unknown."

## 7. Suggested slices (each one is a mergeable PR within the 500-line file limit)

1. **Spike (1–2 days).** Android interceptor serving one bundled `.pmtiles` with the Protomaps style and local glyphs. Check (a)–(c) from §3.2. Measure pack sizes and pan/zoom FPS on the Pixel and Poco test phones.
2. `TileArchive` (PMTiles and MBTiles), `TileArchiveRegistry`, and the interceptor, with unit tests on fixture archives.
3. Offline style builder (`utils/offlineMapStyle.ts`) with tests, bundled glyphs and sprites (Latin ranges only, to save space), and the "Offline" layer option with auto-fallback.
4. Pack manager UI in Settings, plus the world overview pack.
5. Pack build pipeline: `tools/maps/build-pack.sh` (pmtiles extract, POI extraction, metadata), with a GitHub Action that publishes regional packs.
6. Emergency POI layer and nearest list, with the status model.
7. iOS parity (`WKURLSchemeHandler`). After v1.5 if needed.
