# REM 1.6.1 — Bug fixes and security hardening

This release fixes eight reported bugs, merged in PRs #327–#334.

- **#227:** Heart-rate monitoring reports failed GATT creation and retries with the existing bounded reconnect policy.
- **#233:** Android service destruction releases heart-rate monitoring resources, callbacks and its foreground notification.
- **#231:** Plugin authorization requires the current signing certificate. Signing-key changes clear trust, enablement and grants until the new publisher is approved.
- **#230:** The screen-cycle SOS gesture requires six transitions rather than three.
- **#228:** SOS cancellation PINs use Argon2id with random salts. Successful verification upgrades legacy hashes; an incorrect PIN leaves them unchanged.
- **#232:** Plugin Binder lifecycle calls run off Android's main thread, and delayed completion cannot restart a disabled connection.
- **#229:** Checklist versions more than 15 minutes in the future are rejected before persistence. Normal updates remain usable; legitimate future due dates are unaffected. Existing poisoned records are not automatically repaired.
- **#234:** Hardening covers monotonic heart-rate intervals, remote timestamp bounds, SOS alert deduplication, ADB control permissions, idle destination-lock cleanup, tap debounce, mock identifiers and browser operational storage. Existing browser caches are not automatically erased; native durable storage is retained.

## Downloads and updates

`rem-complete.apk` includes the BLE Heart Rate, Watch Status, ATN Rangefinder and goTenna Mesh beta installers. `rem-light.apk` omits installers; `rem-light.aab` is its signed app bundle. Separate plugin APKs are also provided.

Update the plugins as well as REM to receive plugin-side fixes. BLE Heart Rate is 1.0.1, Watch Status is 1.1.5, and goTenna Mesh is 0.2.0-beta.2. Release-signed installations retain signing continuity. Development-signed plugins require a matching development-signed update or an explicit replacement; do not uninstall them without preserving needed configuration.

The 1.6.0 protocol generation is retained. REM 1.5.5 remains incompatible with this generation. goTenna Mesh remains beta.

## Verification

All eight bug PRs passed their applicable CI checks. Developer-assisted Pixel 7 checks passed 10 Android instrumentation tests, 23 selected native ARM64 tests, and an ADB permission control. They covered PIN migration and persistence, checklist clock validation, SOS detector behavior, real signing-key rotation, blocked remote Binder calls, Android service cleanup and hardening regressions. The user subsequently reported that the remaining manual Pixel checklist passed.

The manual results apply to the combined 1.6.1 candidate. Release packaging checks and final installation evidence are recorded in the attached release manifest and checksums. No long-duration battery/load qualification, deterministic hardware null-GATT injection, indefinite Binder-hang recovery, Android 8/9 installer-export qualification or iOS testing is claimed.
