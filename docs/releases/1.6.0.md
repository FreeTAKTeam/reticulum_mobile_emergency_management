# REM 1.6.0 — Performance and power control

This release focuses on reducing unnecessary native CPU work and giving the operator an explicit way to quit REM when networking is not needed. The optional goTenna Mesh plugin is included as **beta**.

## Performance and battery-related improvements

Announce replacement now uses an index instead of scanning all retained history. Peer queries inspect mission-capable peers and saved contacts, and automatic relay selection avoids cloning and sorting the whole announce table. Stored history, transport formats and delivery/retry intervals are preserved.

The earlier release-mode fixtures measured 20,000 announce inserts at **37.68 ms**, compared with **4.177 seconds**, and 1,000 updates at **1.33 ms**, compared with **685.6 ms**. One hundred peer projections over 20,000 announces took **0.969 ms**, compared with **2.786 seconds**. These are deterministic host scaling fixtures, not phone battery-life measurements.

Short Pixel 7 background samples on the earlier optimized `1.5.7-battery.1` build ranged from **10.6–20.4% of one CPU core**, compared with earlier **44–77%** samples. The phone was USB powered and activity differed between captures. No battery-life percentage, negligible background drain, or long-soak improvement is claimed. See the [battery investigation](../testing/android-battery-2026-11-04.md) for attribution, original evidence and limits.

## Quit

Open **More → Quit** to stop REM when it is not needed. After confirmation, REM stops its native runtime and plugins, clears automatic service restore, removes the foreground notification and closes the Android activity. A failed stop leaves REM open for retry. Reopen REM to start networking again. In a browser, Quit stops the runtime and keeps the tab open.

## goTenna Mesh beta

The separate Android plugin **0.2.0-beta.1** connects to goTenna Mesh over Bluetooth LE. It exchanges positions, addressed chat and canonical MECP event codes, and can forward traffic received through REM's other interfaces when explicitly enabled.

Every chat frame carries its recipient's LXMF destination hash. Received local chat uses normal REM conversations; other destinations use compiled LXMF with gateway attribution. Native relay grants and default-off public forwarding control access. Mesh headers are plaintext and unauthenticated, and radio acceptance remains delivery unconfirmed. Physical goTenna BLE/range and cross-device forwarding qualification remain pending. See [setup and wire format](../../plugins/gotenna/README.md).

## Offline installation

- **Complete:** `rem-complete.apk` contains four optional installers: BLE Heart Rate, Watch Status Server, ATN Rangefinder and **goTenna Mesh (Beta)**. Open REM once, then find them under **Downloads / REM Plugins**. Install and enable only the plugins you need.
- **Light:** `rem-light.apk` contains REM without installers; `rem-light.aab` is the signed Light app bundle. Separate plugin APKs are provided, including `gotenna-mesh-beta.apk`.

Both host APKs use the existing REM release signing identity and the same increasing Android version code. A development-signed plugin cannot be updated in place with the release-signed APK. Preserve any needed plugin configuration before choosing to replace a differently signed installation.

The 1.5.7 marker/telemetry format generation is retained. **REM 1.5.5 remains incompatible with this generation.** The new goTenna API requires the updated 1.6.0 host.
