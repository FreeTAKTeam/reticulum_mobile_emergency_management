# REM 1.6.3 — Startup crash fix for busy networks

This hotfix stops REM from crashing at startup on nodes connected to large public networks such as rmap.world.

- **Startup crash:** REM stored every announce it ever heard and never removed any. On a busy network the stored list grew to tens of megabytes, and loading it at startup ran out of memory and closed the app. REM now keeps the 2000 most recently heard destinations, removes older ones when it starts, and never sends the app more than that. Saved peers are stored separately and are not affected. Peers that are no longer in the list reappear the next time they announce.
- **Dependency maintenance:** `rustix` is updated to 1.1.6 for RUSTSEC-2026-0486.

## Downloads and updates

`rem-complete.apk` includes the BLE Heart Rate, Watch Status, ATN Rangefinder, and goTenna Mesh beta installers. `rem-light.apk` omits installers; `rem-light.aab` is its signed app bundle. The plugin APKs are unchanged from 1.6.2 and are attached again so the release stays complete.

1.6.3 is signed with the same key as 1.6.2 and installs over it, keeping existing data. goTenna Mesh remains beta.

## Qualification limits

The fix was tested on a Poco 23013PC75G that was crashing on every launch with 1.6.2. After installing over 1.6.2 with its existing data, REM started and stayed running, with announces and propagation sync working. Automated native and frontend checks pass. The qualification limits listed for [1.6.2](1.6.2.md) still apply.
