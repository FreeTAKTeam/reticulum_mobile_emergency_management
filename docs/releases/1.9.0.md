# REM 1.9.0: Events on the Map

This release puts events on the map, lets you answer your hub in chat, and keeps the hub reachable without waiting for its announce.

- **Events on the map (#371):** the telemetry map shows events as circles coloured by MECP severity. The position comes from the hub's event record when it carries one, otherwise from the MECP coordinates in the event text. Tap a circle to see the category, callsign and text. Events without a position stay off the map; deleted events are removed from it.
- **Reply to the hub (#369):** chats from the configured Reticulum Community Hub (RCH) can now be answered from the Inbox, even though the hub is not a saved Inner Circle peer. Power saver still pauses hub chat.
- **Hub Link (#367):** in semi-autonomous and connected modes REM announces when a TCP interface comes up (at most once a minute), keeps a Link to the hub, and waits up to 12 seconds for a path before a direct send to the hub fails. Autonomous mode is unchanged. The LoRa-only rule against proactive Links still applies.
- **Long event text (#365):** long words wrap instead of widening the Events screen, so the delete and add buttons stay on screen. Household status wire text is no longer shown as raw MECP details.
- **MECP decoding (#360, #368, #372):** the decoder now runs against the MECP free-text conformance vectors. When a message has several timestamps or person counts, the first one wins, as MECP rule 5 requires, and `0pax` is ignored.

REM 1.9.0 builds against Fabric (formerly LXMF-rs) release `v0.17.0` ([`99fc770e83ed`](https://github.com/FreeTAKTeam/LXMF-rs/commit/99fc770e83ed56eec81a23d8b4b864fe2cfde80e)).

## Requirements

- Hub event positions need an RCH release that sends `latitude` and `longitude` with mission log entries. With an older RCH, events show on the map only when their text has MECP coordinates.

## Qualification limits

- Automated checks pass: the native tests (event position parsing and storage, hub Link decisions), the frontend unit tests (chat policy, MECP conformance), the end-to-end map tests in the browser, and the release unit tests.
- **Not yet tested on devices:** events on the map, replying to the hub, and the hub Link and path wait against a live hub, including dropping and restoring TCP and the LoRa-only setup.
- Events created in REM do not carry the device position yet.

The qualification limits listed for [1.8.0](1.8.0.md) and [1.7.0](1.7.0.md) still apply.
