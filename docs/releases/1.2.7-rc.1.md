# REM 1.2.7-rc.1 Release Notes

`1.2.7-rc.1` is an Android stabilization prerelease built against LXMF-rs
`v0.9.5` (`7cafc5b4be21ff4f777d0f2300cfb79e5d0da23c`). It does not redesign the
wire protocol or duplicate LXMF behavior outside the compiled Rust bridge.

## Highlights

- Local runtime startup no longer waits for RCH registration. Disabled or
  unavailable RCH and degraded network interfaces do not trap users behind the
  splash screen.
- Native failures carry stable code, operation, retryability, and causal
  diagnostics through JNI and the exported node-client error type.
- All Java JNI operations contain Rust panics and retain compatible return
  values.
- Rust error sources and numeric boundaries were audited; production panic,
  unwrap, expect, unreachable, and first-party unsafe implementation code are
  denied.
- Dependency lockfiles resolve active npm and RustSec vulnerabilities without
  Capacitor, TypeScript, MapLibre, or other major migrations.
- CI runs strict Rust checks, pinned/current LXMF compatibility, npm audit,
  mobile/web builds, and all 74 desktop/mobile Chromium cases.
- The user manual adds first-launch, peer/chat, EAM/MECP, checklist, and SOS
  examples with recovery guidance.

## Supported Scope

- Android application and Android plugin SDK/examples.
- TCP-only, RNode LoRa-only, and mixed TCP/LoRa operation after the issue #168
  physical-device matrix passes.
- Autonomous, Semi-autonomous RCH, and Connected RCH modes as described in the
  architecture documentation.

iOS compilation and CocoaPods are not release gates for this prerelease.

## Known Limitations

- Interface configuration changes require saving and restarting REM before the
  release matrix is evaluated.
- Bluetooth Classic/SPP and USB settings are represented but remain explicitly
  unsupported until their Android transport backends are connected.
- `bincode 1.3.3` and transitive `paste 1.0.15` are unmaintained but have no
  reported vulnerability; compatibility-sensitive migration is deferred.
- PDF and DOCX manuals under `docs/` are archived snapshots. Markdown is
  authoritative.
