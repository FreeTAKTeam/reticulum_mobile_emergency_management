# REM 1.2.7 Release Notes

REM `1.2.7` is the stable Android release built against LXMF-rs `v0.9.5`
(`7cafc5b4be21ff4f777d0f2300cfb79e5d0da23c`). It promotes the validated
`1.2.7-rc.1` stabilization baseline and adds team-scoped operations, local team
sharing, presence fixes, and the redesigned Peers and Manage Teams experience.

## Highlights

- Local and RCH teams now scope every outbound recipient set while operational
  timelines remain shared. Yellow is the default team, local aliases remain
  private, and matching local/RCH color teams merge without modifying hub-owned
  membership.
- Teams can be exported as versioned QR codes and imported by another REM
  client. Imports validate canonical team colors and destinations, merge
  members safely, and preserve the receiving client's local alias.
- The Peers screen has a compact active-team selector beside Announce, keeps
  Discovery, Peers, and Hub workflows available, and provides active-roster
  connection controls. Settings now opens a dedicated Manage Teams page.
- Presence and semi-autonomous hub behavior use durable cached directories and
  local reachability resolution rather than repeatedly asking RCH to classify
  active peers. The normal 1,800-second announce interval is respected.
- Chat, EAM, events, checklists, telemetry, and SOS routing fail closed when the
  active team has no valid recipients and carry standard LXMF `FIELD_GROUP`
  metadata for the canonical team UID.
- Node stop returns to the regular stopped screen, and unavailable or disabled
  interfaces no longer leave REM behind an indefinite loading overlay.
- Event parsing retains MECP codes when optional text follows the event code,
  and send failures expose classified network errors instead of ambiguous UI
  failures.
- Native failures retain stable codes, operations, retryability, and causal
  diagnostics across Rust, JNI, UniFFI, and the TypeScript node client. Rust
  panic and unsafe boundary checks remain enforced.
- The Markdown user manual is authoritative and includes first-launch, peer and
  team setup, chat, EAM/MECP, checklist, SOS, recovery, and developer examples.

## Supported Scope

- Android 8.0/API 26 or newer.
- Autonomous, Semi-autonomous RCH, and Connected RCH modes described in the
  architecture documentation.
- TCP operation, including peer discovery and connection, chat, EAM/MECP,
  events, checklists, telemetry, SOS, restart recovery, and team-scoped routing.
- Local color teams and additive read-only canonical teams supplied by RCH.

iOS compilation and CocoaPods are not release gates for `1.2.7`.

## Known Limitations

- The physical RNode LoRa-only and mixed TCP/LoRa issue #168 rows, including the
  60-minute mixed-load soak, remain preview scope. They are recorded as pending
  in the manual release matrix and are not claimed as completed by this release.
- Interface configuration changes require saving and restarting REM before the
  release matrix is evaluated.
- Bluetooth Classic/SPP and USB settings are represented but remain explicitly
  unsupported until their Android transport backends are connected.
- `bincode 1.3.3` and transitive `paste 1.0.15` are unmaintained but have no
  reported vulnerability; compatibility-sensitive migration is deferred.
- PDF and DOCX manuals under `docs/` are archived snapshots. Markdown is
  authoritative.
