# REM 1.4.1

REM 1.4.1 updates the compiled networking stack to LXMF-rs `v0.13.0`, pinned to
release commit `fbc75b86e15550722923b366398f0a4116182894`.

## Changes

- Build the native runtime and Android libraries against the released `0.13.0`
  Reticulum, transport, LXMF wire, SDK, runtime, and reference crates.
- Handle the new outbound Resource rejection event explicitly in REM diagnostics;
  the compiled LXMF runtime remains responsible for delivery outcomes.
- Use the updated shared-reference receipt-handler API without changing transport
  ownership or duplicating protocol behavior.
- Include the community foundation already merged into REM: household profiles,
  peer Circle preferences, signed Block Code review, native-backed household
  actions, and power-saver policy.
- Keep production CI and Android plugin checks pinned to the same release commit.

## Compatibility and field-test scope

LXMF-rs v0.13.0 includes selected changes from Python Reticulum 1.5.5; it does
not claim full Reticulum 1.5.5 parity. See the
[upstream release notes](https://github.com/FreeTAKTeam/LXMF-rs/releases/tag/v0.13.0).

Android is the release target. Native libraries are rebuilt for `arm64-v8a`,
`armeabi-v7a`, and `x86_64` with 16 KiB ELF alignment. The REM UniFFI and JNI
contracts are unchanged.

The earlier REM 1.4 two-phone LoRa evidence does not validate this new APK.
Physical-radio, mixed-interface, and two-phone acceptance must be repeated with
these exact artifacts. Known EAM and checklist replication gaps described in
[REM 1.4](1.4.md) are not claimed fixed by this dependency update. See the
[manual release matrix](../rem-1.2-manual-release-gate.md).
