# REM 1.5.4

REM 1.5.4 redesigns Settings into a grouped index with one page per topic,
rebuilds the setup wizard on the same forms, and fixes problems found while
field testing 1.5.3: invisible sent chat messages, raw household codes in
Events and a misleading household card. SOS now posts MECP events, and the
runtime gains the household situation command that a later UI will use. The
compiled networking stack is unchanged: LXMF-rs `v0.14.0`, pinned to release
commit `7822b608f2cd2debd8170895bc580d01dda5356e`.

## Highlights

- **Settings is now an index with focused pages.** The index groups rows as
  You, Connectivity, Sharing, Emergency and Device, and each row shows its
  current value. Each topic (Identity, Network interfaces, Routing & hubs,
  Location sharing, Map, SOS, Battery saver, Plugins, Share this setup, Node &
  diagnostics, About) has its own page with its own Save and Discard. Leaving
  a page with unsaved edits asks first. Fields that need a node restart carry
  a badge, and after saving one the index shows which settings are waiting
  for a restart, with a Restart button. Trigger SOS now asks for
  confirmation, and the hub API URL and key fields are visible again.
- **The setup wizard uses the same forms.** Steps follow the Settings index:
  Welcome, Identity, Network (TCP, optional LoRa), Routing, Location sharing,
  SOS and Review. Validation is shared, so a call sign is now required in
  both places. Power saver and preferred map are no longer asked during
  setup; they stay in Settings.
- **Sent chat messages are visible again.** A long unbroken message, such as
  an old LoRa test string, widened the thread and pushed sent bubbles off
  screen. Long text now wraps.
- **Household status reads correctly.** Household status (B04) events show
  "Household status: All Home" with household details instead of the raw
  `REMCS1:` code. The dashboard household card shows when the status was
  actually shared, no longer counts this phone as a nearby household, and is
  a single badge with *Change*. "1 Missing" is now "Someone Missing" (the
  wire value stays `one_missing`). Choosing the highlighted status now shares
  it, so a phone that never published can send its first status.
- **SOS posts MECP events.** The runtime posts `MECP/0/B01 #SOS_<incident>`
  when an SOS becomes active and `MECP/2/B03` when an active SOS is
  cancelled, as ordinary replicated events in the SOS traffic class.
  Replication is queued, so triggering and cancelling return in about 1.5 s.
- **Household situation runtime (no UI yet).** The Rust runtime can turn one
  chosen situation into the B04 beacon, MECP event and EAM update it implies,
  with a household mode (Off, This phone reports, Another phone reports).
  This is exposed through the bridge for the coming UI; operators will not
  see it in 1.5.4. See [architecture](../architecture.md).
- **Other fixes.** RNode pairing stays open and shows its error when
  selecting a device fails. Save feedback ("Saved." or an error) clears when
  you edit or discard the form. Settings pages keep their styles in release
  builds.
- **Dependencies unchanged.** LXMF-rs stays at `v0.14.0` (commit
  `7822b608f2cd2debd8170895bc580d01dda5356e`) and `r3akt-map-core` stays at
  `19de27f419373c543fe6154aab2a3c027938b65d`. Wire formats for EAM, REMCS1 v1
  and MECP are unchanged.

## Known limitations

- An SOS activated after a non-zero countdown does not post B01. Release
  settings force the countdown to zero.
- The limitations listed in [REM 1.5.3](1.5.3.md) and [REM 1.5.1](1.5.1.md)
  still apply.

## Compatibility and field-test scope

Android is the release target. Native libraries are rebuilt for `arm64-v8a`,
`armeabi-v7a`, and `x86_64` with 16 KiB ELF alignment.

Field evidence from 2026-10-19: on a Pixel 7 running
release-signed development builds of these changes, sent chat messages, the
decoded household event, the compact household card and the restyled
Settings pages displayed correctly, and a live SOS trigger and cancel were
acknowledged by a Poco X5 Pro. Those runs did not use these release
artifacts. Physical LoRa, mixed-interface and hub-connected (RCH) acceptance
were not repeated for these artifacts.
