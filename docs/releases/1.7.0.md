# REM 1.7.0 — TEAM sync through the hub and smoother restarts

This release makes Semi-autonomous TEAM sharing reach members that REM knows only from its Reticulum Community Hub (RCH), fixes a restart problem that could make REM unresponsive, and makes a hub easier to select.

- **Hub-only TEAM members receive updates:** in Semi-autonomous mode, a member of the active TEAM that REM knew only from the RCH directory received no markers, events or telemetry once REM had learned its identity. REM now sends to those members directly.
- **Unresponsive app after a restart:** after a restart, REM could rewrite its saved-peer list about ten times a second while a saved peer was online. This kept two CPU cores busy and made the app slow to respond. A restart no longer creates the duplicate saved entries that caused it, and a duplicate left by an earlier version is removed when its real peer is next seen online. Until then it shows as a saved peer without a name and can be deleted in Peers.
- **Hub picker:** Settings → Routing → "Hub from announces" now lists hubs heard on the network and stores the hub's LXMF delivery address, which is where TEAM directory requests are sent. Hubs appear only when they run an RCH release that announces its hub features.
- **Hub refusals shown:** when RCH rejects the TEAM peer directory request (for example "TEAM membership is required"), REM now reports the hub's reason instead of a generic network error, and keeps the last list it downloaded.

## Downloads and updates

`rem-complete.apk` includes the BLE Heart Rate, Watch Status, ATN Rangefinder, and goTenna Mesh beta installers. `rem-light.apk` omits installers; `rem-light.aab` is its signed app bundle. The plugin APKs are unchanged from 1.6.2 and are attached again so the release stays complete.

1.7.0 is signed with the same key as 1.6.3 and installs over it, keeping existing data. goTenna Mesh remains beta.

## Qualification limits

Tested on a Poco 23013PC75G in Semi-autonomous mode against an updated RCH, using signed test builds of the same changes installed over existing data:

- a new marker was delivered directly to a TEAM member that is listed only by the hub;
- with the restart fix, link-maintenance activity fell from about 9,000 to about 130 log lines per minute and CPU use returned to single digits;
- the TEAM list downloads, a refusal shows the hub's reason, and the hub is classified from its announce.

Automated native and frontend checks pass. The final 1.7.0 APK itself was not installed on a device.

Known issue: sends to some saved peers in the local TEAM can still fail with `invalid config` at send time. This is not new in 1.7.0.

The qualification limits listed for [1.6.3](1.6.3.md) still apply.
