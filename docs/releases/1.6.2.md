# REM 1.6.2 — Sensor telemetry and runtime updates

This release updates the native LXMF runtime and adds provisional R3S/1 sensor geometry support.

- **Sensor geometry:** Authorized plugins can publish sensor geometry and independent origin positions. REM can display received geometry on its existing map. Plugin API 1.4 separates permissions for publication, network sharing, and video metadata.
- **Runtime and storage:** The LXMF-rs source pin advances to 0.16.1, and REM, LXMF-rs, and the shared RCH map library use aligned SQLite dependencies. The migration was tested with an existing marker database and uncheckpointed WAL.
- **Dependency maintenance:** Tokio and UniFFI were updated, and the native and binding-generator lockfiles pass the configured dependency audit. Generated Kotlin bindings use the matching native library and generator.

## Downloads and updates

`rem-complete.apk` includes the BLE Heart Rate, Watch Status, ATN Rangefinder, and goTenna Mesh beta installers. `rem-light.apk` omits installers; `rem-light.aab` is its signed app bundle. Separate plugin APKs are also provided.

Release-signed installations retain signing continuity. Development-signed plugins require a matching development-signed update or an explicit replacement; preserve any needed configuration before replacing a differently signed installation. goTenna Mesh remains beta.

## Qualification limits

R3S/1 uses provisional sensor ID 128; interoperability agreement and physical camera, drone, radio, and cadence qualification remain open. Some Sideband repacking paths can discard this optional extension. The RCH daemon cannot yet cancel or re-authorize a sensor retry that it has already admitted, so immediate network revocation is not established. Video endpoint metadata requires explicit approval; video is not carried over the sensor telemetry path.

The changes have automated native, frontend, plugin, binding, and emulator coverage. Physical-device and radio tests for the updated LXMF runtime and R3S/1, long-duration battery/load testing, and iOS qualification are not established by those checks. See the [R3S/1 evidence](../goals/r3s-telemetry/EVIDENCE.md) and [manual release matrix](../rem-1.2-manual-release-gate.md) for the remaining gates.
