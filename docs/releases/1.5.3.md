# REM 1.5.3

REM 1.5.3 lets display plugins follow the map around you and makes plugin
settings readable on a phone. It was prompted by the ATN Rangefinder plugin,
which now shows nearby REM markers on an ATN Binox automatically. 1.5.2 was an
internal test build and was not published. The compiled networking stack is
unchanged: LXMF-rs `v0.14.0`, pinned to release commit
`7822b608f2cd2debd8170895bc580d01dda5356e`.

## Highlights

- **Plugins can follow nearby markers (new, opt-in).** A new plugin capability,
  `mapNearbyRead` ("Read all map markers near this device"), and operation
  `map.markers.nearby` return the map markers within a radius of this phone's
  own position, nearest first. Results have at most 50 markers and leave out
  notes. A display plugin can mirror the operational map without the operator
  sharing each marker. The operator grants it once per plugin in
  **Settings → Plugins**, and it can be revoked there at any time. Older REM
  versions ignore the capability. See the
  [plugin system documentation](../plugins/android-plugin-system.md).
- **Readable plugin settings.** Each plugin card lists its permissions one per
  line, so none are pushed off screen. Before, long Android permission names
  widened the card and hid some checkboxes. The card summarizes what the
  plugin uses on the phone in plain words (Bluetooth, location,
  notifications, running in the background). The ID, package, publisher
  fingerprint and raw Android permissions move under **Technical details**.
- **Dependencies unchanged.** LXMF-rs stays at `v0.14.0` (commit
  `7822b608f2cd2debd8170895bc580d01dda5356e`) and `r3akt-map-core` stays at
  `19de27f419373c543fe6154aab2a3c027938b65d`.

## Known limitations

- REM refreshes the phone's own position (the plugin "observer") only at the
  telemetry publish interval, and the web layer's timer does not run while REM
  is in the background. Plugins that need a fresh position, such as ATN
  Rangefinder, read the phone's GPS themselves.
- The limitations listed in [REM 1.5.1](1.5.1.md) still apply.

## Compatibility and field-test scope

Android is the release target. Native libraries are rebuilt for `arm64-v8a`,
`armeabi-v7a`, and `x86_64` with 16 KiB ELF alignment.

Field evidence from 2026-10-18: on a Pixel 7 (GrapheneOS) running development
builds of this code, the ATN Rangefinder plugin received nearby markers and
showed them on a Binox 4K. A plugin-created marker replicated to a Poco X5 Pro
running REM 1.5.1. That run used development builds, not these release
artifacts. Physical LoRa, mixed-interface and hub-connected (RCH) acceptance
were not repeated for these artifacts.
