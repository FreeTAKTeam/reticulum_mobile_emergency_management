# REM 1.2.8 Release Notes

REM `1.2.8` improves LXMF interoperability while retaining compatibility with
REM `1.2.7` and older deployed REM clients.

## Chat interoperability

- Replies to persisted inbound LXMF conversations no longer require the sender
  to be saved as an REM peer.
- The native runtime attempts the sender's current LXMF route first and uses the
  configured propagation relay when direct delivery is unavailable.
- Reply authorization is limited to destinations with inbound chat history. It
  does not save the sender, create a managed peer link, or authorize arbitrary
  destination hashes.
- Submitted chat text is inserted into the conversation before route checks.
  Failed sends remain visible with their error and a Retry action.
- Retry reuses local failed messages or the native LXMF retry operation after a
  message has been accepted by the runtime.

## Announce and receipt compatibility

- REM advertises its capabilities in standard structured LXMF delivery announce
  metadata.
- The mobile capability decoder accepts structured metadata, older structured
  REM metadata, and legacy text announces.
- Standard LXMF delivery receipts remain authoritative. Compatibility handling
  for older named REM clients remains available without affecting non-REM
  clients.

## Platform

- Android version name: `1.2.8`
- Android version code: `262032110`
- LXMF-rs baseline: `v0.9.5` plus the structured announce metadata integration
  under review in LXMF-rs PR #499.
- iOS compilation and CocoaPods are not release gates for this build.
