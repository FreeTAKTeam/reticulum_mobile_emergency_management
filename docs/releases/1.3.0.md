# REM 1.3.0

REM 1.3.0 adds direct Android Bluetooth transports for RNode-backed LoRa
connectivity.

## Highlights

- Connect an RNode over Bluetooth Low Energy using Nordic UART Service.
- Connect compatible RNodes over Bluetooth Classic Serial Port Profile.
- Scan, pair, select, and reconnect RNodes from Android.
- Negotiate a 517-byte BLE ATT MTU before subscribing to RNode notifications,
  avoiding truncated KISS command responses at Android's 23-byte default.
- Preserve REM's conservative 20-byte outbound GATT write chunks after MTU
  negotiation, so older RNode BLE firmware is not handed a complete signed
  announce in one large characteristic write.
- Keep constrained RNode-only LoRa sessions available for on-demand traffic by
  suppressing background saved-peer link warming and automatic propagation
  relay polling, which can otherwise delay link proofs past their deadline.
- Hold Reticulum payloads until RNode probe and radio configuration startup is
  validated.
- Accept older RNode firmware that omits only the startup radio-state echo when
  every other probe and radio parameter validates; real configuration
  mismatches and hardware errors remain fatal.
- Keep a JNI global reference to the Android RNode transport manager so native
  worker threads can reconnect without Android class-loader failures.
- Use the RNode transport's 508-byte packet MTU so signed LXMF announces reach
  the radio instead of being rejected by the generic LoRa payload limit.
- Use USB to place a compatible RNode into Bluetooth pairing mode.
- Report RNode connection and readiness independently from local runtime
  readiness.
- Keep the compiled LXMF-rs stack as the owner of Reticulum and LXMF protocol
  behavior while Android supplies the Bluetooth byte transport.

## Compatibility

- Android API 26 or newer.
- LXMF-rs `v0.9.9` baseline with RNode startup and BLE write compatibility at
  immutable revision `b7e4018b06f1ef5cb4e226a2b353e1609ccf06f7`.
- RNode firmware `1.83` or newer is recommended for modern Android BLE pairing.

Older firmware may use REM's narrowly scoped missing-radio-state compatibility
path, but updating the RNode is still recommended.

See the [RNode Bluetooth connectivity guide](../rnode-bluetooth-connectivity.md)
for pairing, configuration, verification, and troubleshooting steps.
